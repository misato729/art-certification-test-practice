# 実装・検証

## 開始時に読むもの

- [AGENTS.md](../../../AGENTS.md)、[構成](../../architecture.md)、[検証手順](../../testing.md)。
- `git status --short`、[進捗一覧](../state.json)、対象タスクと最新の引き継ぎ。

## 共通の進め方

- Nuxt / Nitro / Better Auth / Prisma / PostgreSQLという現在の構成を優先する。別サービスのDB方式・認証・移行履歴を持ち込まない。
- 依頼を小さく分け、受入条件・変更範囲・必要な検査・評価回数の上限を着手前に決める。
- 既存の未コミット変更を保護し、担当ファイルを分ける。進捗一覧の更新担当は1名にまとめる。
- 関連する軽い確認から始める。重いテスト・型検査・ビルドは順番に実行し、無関係な全件検査を毎回行わない。
- UIはPCとスマートフォンを実操作で確認し、DBは反復操作・変更しない場面・編集削除を影響範囲に応じて確認する。
- 検査を実行した結果と、過去の記録を読んだだけの範囲を区別する。独立レビュー後、ゲートを通った作業だけを完了とする。

## 完了後

- 変更したファイル、検証の範囲と結果、未確認事項、次の行動を記録する。
- ローカル実装・コミット・push・公開・本番確認を分ける。引き継ぎ記録は権限を増やさない。
- テンプレートには派生サービスの進捗・完了記録を同梱しない。新しいコピーは世代0・空のタスク一覧から始まる。
