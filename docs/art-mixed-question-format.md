# 美術史問題と資料参照型問題の表示

## 対象と根拠

ユーザーが提供した「2級公式問題集」の冊子9ページでは、関連知識を学ぶために大問形式を採用していることが説明されている。「2級 サンプル問題」では通常の独立小問に加え、PDF5ページに共通の作品・資料を参照する複数の活用問題がある。これを踏まえ、通常問題と資料参照型の活用問題の両方を扱う。

これは本試験の全問の配置を確定する実装ではない。既存の `config/exam.json` にある各セットの出題区分を使い、知識・情報の活用問題と別枠の実践問題を区別する。公式問題・正答・図版・原典PDFを本パッチへ転載しない。

## 表示と移動

- 通常問題は1問ずつ表示する。共通資料への既存の参照がある場合は、資料を省略せず「この問題の資料」として設問内に表示する。必要な下線・図版・表を失わせない。
- 知識・情報の活用問題は「共通資料・図版」を別パネルに表示する。APIが返した資料だけを表示し、表示していない小問の正答や解説を取得・共有しない。
- 共通資料の開閉状態は同じ問題群で保つ。状態に保存するのは開閉の真偽だけであり、本文・正答・認証情報は保存しない。下線・空欄の参照ボタンは対象資料を開いてからフォーカスを移す。
- 同じ活用問題群の小問リンクは、現在の演習対象に含まれる公開位置だけを表示する。5問固定のグループを仮定しない。
- サイドバーは、作問用のテーマ群を「大問」と並べるのではなく、設定上の「美術史問題」「知識・情報の活用問題」を表示する。区分を選んだ場合はその区分の公開小問だけを演習し、次の区分へ勝手に進まない。模試名のリンクからは模試全体を演習できる。
- トップページの大問数表示を外し、現在の問題数は引き続きAPIの実数を使う。別枠の実践問題は対象外である旨を記載する。

## ランダム演習

通常問題は小問単位、活用問題は実際のAPIの `group.id` 単位でシャッフルする。活用問題群の中ではAPIの `question_numbers` の順序を保つ。選択していない小問や未公開の小問を補完しない。異なる模試の同じグループIDは混同しない。

新しく開始した通常ランダム演習のURLに `random_unit=materials-v1` を付ける。旧URLにこの指定がなければ従来のシャッフルを使う。トップ・演習開始ページ・演習本体が同じ関数を使うので、同じ条件・公開カタログ・seedの間では順序が一致する。

「間違えた問題」の復習は従来の対象・順序を維持する。復習対象外の問題を追加しない。その場合でも各小問に必要な資料は表示する。

## データを変更しない

本パッチにDBマイグレーション、seed、import、直接SQLは含めない。問題ID、選択肢ID、正答、解説、本文、図版URL、共通資料の参照、公開状態、解答履歴、お気に入りは変更しない。

**表示方式を変えても、既存の設問文を自動的に再作問したり、独立した活用5問を新しい共通テーマの問題群に作り替えたりはしない。** 現状の活用問題が各1問のグループなら、そのまま各1問として扱う。

通常問題に「前問の作品」等の依存が残る場合、それが解消されたとはみなさない。新規の問題作成・既存問題の再編集は、必要資料と正答根拠を確認したうえで管理画面・共通Writerで実施する。リード文をまとめて削除しない。

既存のジャンル絞り込み未実装、採点APIの再送制御等は今回の範囲外。

## 実装上の前提

出題区分の正本は `config/exam.json` の `exam.sets[].sections`。区分の範囲を80・85という数値で固定しない。活用区分は現行の正式な設定名 `知識・情報の活用問題` で識別する。この設定名を変更する場合は `APPLICATION_SECTION_TITLE` と関連テストも合わせる。

使用するAPIの既存フィールドは `group`、`shared_passages`、`passage_references`。新しいAPIレスポンスや権限緩和は不要。

## 検証

追加の `artPracticeFormat.test.ts` は区分境界、疎な公開位置、未公開区分、ロック、旧シャッフル互換、100種類のseedでの問題群保持、入力非変更を検査する。`artPracticeWiring.test.ts` は画面・開始ルートの配線と資料保持をソースで確認する。既存の `examSidebarLayout.test.ts` は区分表示の新仕様に合わせる。

```sh
# リポジトリのルートから、DB不要の追加テスト
node --experimental-strip-types --test frontend/tests/artPracticeFormat.test.ts frontend/tests/artPracticeWiring.test.ts

# 依存パッケージ導入済みの環境で、公開前の全体検査
cd frontend
npm test
npm run typecheck
NITRO_PRESET=static npm run generate
```

公開前には、PC・スマートフォンの両方で、通常問題の図版、活用問題の資料展開、下線・空欄への移動、同一問題群の次問、区分末尾、既存URLからの復習・履歴表示を実操作で確認する。単体テストの成功を本番UI・DB検証の成功として扱わない。
